# 升级项：P49 选题与账户级超时语义（2026-11-17）

## 争议一：P49 的编号用在哪里

P48 段落登记了两个候选：P48.2（店级目标变更后预算池同页失效）与「P49 护栏临时放宽的提前结束入口（若走查发现人确实需要）」。本轮走查看到的是另一条更薄的链路：账户上期结论只活在工作台，收件箱不出现、人无处表态（模拟跨月后收件箱未处理数不变）。这属于「处理升级」在账户级的空洞，而前两个候选分别是同页数值刷新与一个尚无证据支持的入口。

### 选项

1. 先做 P48.2：修复展示一致性，人少一次「这数字是不是过期了」的怀疑；不改变 Agent 承担的判断。
2. 先做护栏提前结束：给临时放宽加「立即收回」，但走查中没有出现人需要提前收回的场景，属于假设需求。
3. 先做账户结算待办：把 Agent 已算出的上期结论送进收件箱，给出「沿用 / 下调」两个可执行立场并路由 Owner。

### 选择

选 3，编号 P49；原「护栏提前结束」继续挂起，P48.2 作为下一轮候选。理由：方案 3 让 Agent 多承担「算清上期、判级、路由、到期收口、旧条目清理」，人只做一次立场选择，错了可在二次确认气泡、账户目标行和处理记录三处拦下；方案 1 只是展示修复，方案 2 缺少需求证据。编号占用了原候选标签，故在此留痕。

## 争议二：账户级待办超时后要不要替人确认

账户级条目没有门店策略，P30/P34 的既有口径是「超时按默认建议收尾」。

### 选项

1. 超时＝沿用并记为本月已确认（自动续约，数字不变）。
2. 超时＝只关闭提醒，不写账户目标；账户目标行继续显示「上期 · 待确认」。
3. 超时不关闭，永久提醒。

### 选择

选 2。理由：账户承诺的「确认」属于人，P48 明确不自动结转；沿用虽然不改数字，但会把「未确认」变成「已确认」，是不可逆的状态推进。选 2 不改变任何数据，提醒已送达一次，工作台上「待确认」仍然可见，下个周期会按新的上期重新生成待办；选 3 会形成永久噪声，与「升级项只累计、不作为阻塞」冲突。

## 影响

- 本轮只新增账户级待办与两个补救动作，不改单店结算、分配、预算池与护栏。
- 若人希望「超时自动沿用」，只需把巡检里账户分支改为调用 `applyAccountGoalSettlementRemedy('uphold')`，一条分支即可回退。

## 争议三：P54「方案仍按旧输入生成」回执放在哪里

目标/护栏改过、Agent 重跑失败时，需要一个可见回执。可选位置有三个。

### 选项

1. 收件箱新增一条「方案已过期」待办，要求人处理。
2. 只在经营周期卡显示过期提示（扩展现有 `guardChanged`）。
3. 在目标卡（人刚操作的位置）显示过期回执并提供「让 Agent 重跑」。

### 选择

选 3，并把方案输入比较同步补进经营周期卡的既有提示（2 作为次要展示保留）。理由：这是一致性状态，重跑成功即消失，进收件箱会变成需要人关闭的噪声，违背「升级项只留真正需要人判断的事」；而目标卡正是人保存目标/护栏的位置，回执与补跑按钮放在这里，人不用跳页核对。判定只比对方案自己记录的输入快照（护栏 + 目标/指标/优先级），不看时间戳，避免结算或进度刷新造成误报；不改任何保存口径，失败时目标与护栏仍以人的输入为准，可随时回退。

### 影响

- 不再新增收件箱条目类型，不扩大待办的语义。
- 若人希望过期状态也进收件箱，只需在巡检里把该状态映射为一条升级项，回执数据已经具备。
